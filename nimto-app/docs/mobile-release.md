# Mobile and PWA release guide

## Environments

The mobile application defines four EAS Build profiles in
`apps/mobile/eas.json`:

| Profile       | Distribution                | OTA channel   |
| ------------- | --------------------------- | ------------- |
| `development` | Internal development client | `development` |
| `preview`     | Internal tester build       | `preview`     |
| `staging`     | TestFlight / Play testing   | `staging`     |
| `production`  | App Store / Play production | `production`  |

`runtimeVersion.policy` is `appVersion`. JavaScript and asset updates can only
reach binaries with the same compatible app version. Increment the app version
whenever native modules, permissions, bundle configuration, or native code
changes.

The full editor release introduces
`@react-native-async-storage/async-storage` for on-device draft recovery. Ship
this release in a newly built iOS/Android binary with a new app version before
publishing later JavaScript-only editor updates over OTA.

## One-time Expo account linking

This repository intentionally does not contain Expo credentials. An authorized
project owner must run:

```bash
cd apps/mobile
npx eas-cli login
npx eas-cli init
npx eas-cli update:configure
```

Commit the project ID and update URL generated by `eas init` and
`eas update:configure`. Store API URLs in the corresponding EAS environments:

- `EXPO_PUBLIC_API_URL`
- `EXPO_PUBLIC_WEB_URL`

Do not commit store credentials, signing files, API keys, or access tokens.

## Build and submission

Create staging and production binaries from the same reviewed commit:

```bash
npx eas-cli build --profile staging --platform all --auto-submit
npx eas-cli build --profile production --platform all --auto-submit
```

Test the staging binaries through TestFlight and Google Play testing before
releasing production.

## OTA updates

Only publish an OTA update after typecheck, lint, native export, API build, and
staging-device verification:

```bash
npx eas-cli update --channel staging --message "Describe the change"
npx eas-cli update:republish --destination-channel production
```

For a gradual production release:

```bash
npx eas-cli update --channel production --rollout-percentage 10
npx eas-cli update:edit
```

Rollback options:

```bash
npx eas-cli update:rollback
```

OTA must not be used to introduce a native dependency or bypass App Store or
Play policy review.

## Universal links

The custom `mynimto://` scheme is configured. HTTPS Universal Links/App Links
must be enabled after the final production domain and store signing identities
exist:

1. Add the production domain to iOS `associatedDomains` and Android HTTPS
   intent filters.
2. Publish `apple-app-site-association` using the Apple Team ID and bundle ID.
3. Publish `assetlinks.json` using the Play signing SHA-256 certificate.
4. Verify invitation and event routes on physical staging devices.

Do not publish placeholder signing fingerprints.

## PWA releases

Both the Next.js site and the Expo static web export can be deployed as PWA
surfaces. The Expo export includes its own manifest, icon, service worker, and
offline route. Keep them on separate origins or non-overlapping service-worker
scopes. Both service workers cache static assets only; authenticated API
responses are excluded.

After deployment, verify:

1. `/manifest.webmanifest` and `/sw.js` return 200 over HTTPS.
2. Installation works in Chrome/Edge and through Safari Add to Home Screen.
3. Offline navigation reaches `/offline`.
4. Login, event, and invitee API responses are not present in Cache Storage.
5. A subsequent deployment shows the in-app update notice.

For the Expo host PWA, run `npm run export --workspace @nimto/mobile`, publish
`apps/mobile/dist` to an HTTPS static host with clean-route rewrites, and verify
the catalogue previews, login, editor autosave, publish flow, and `/offline`
fallback from the deployed origin.
